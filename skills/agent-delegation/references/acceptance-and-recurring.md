# Приёмка и повторяющиеся задачи

## Приёмочный протокол

1. Убедись, что артефакт реально существует и доступен: файл открывается, ссылка ведёт на нужное место, интерфейс работает.
2. Проверь критерий «Готово, когда…» отдельно от описания работы исполнителя.
3. Проверь критические инварианты: целостность исходных данных, неизменность базового метода, правильность крайних случаев.
4. Для кода: тесты и демонстрация на целевом окружении; для исследования: доказательные цитаты и первоисточники; для таблицы: происхождение чисел и расчётов; для сайта: проверка основных пользовательских сценариев.
5. Запиши, что именно не проверено. Признавай пустой список ошибок законным итогом рецензии.

## Независимый рецензент

Промпт:

> Проверь результат так, будто хочешь опровергнуть его ключевые утверждения. Приводи только замечания, для которых есть конкретное доказательство и действие по исправлению. Три существенные проблемы ценнее десяти косметических. Если доказанных проблем нет, верни пустой список. Не переписывай результат и не инициируй повторную проверку бесконечно.

Отчёт критика является консультацией. Автор/агент-исполнитель сверяет возражения с фактами; пользователь принимает решения с высокой ценой ошибки.

## Повторяемая задача

До включения расписания:

- Процесс успешно выполнен вручную на нескольких типичных кейсах.
- Сохранены критерии качества и эталонный пример результата.
- Есть источник истины и контроль изменений между запусками.
- Перечислены источники, которые могут оказаться недоступны.
- Есть правило исключения устаревших и повторных пунктов.
- Установлены лимиты доступа, расходов и числа попыток.
- Первая внешняя публикация или отправка выполняется только после одобрения.

## Формат регулярной сводки

1. Что нового и почему важно.
2. Проверяемые цифры/цитаты со ссылками.
3. Что требует действия пользователя.
4. Какие источники не открылись и какие разделы могли оказаться неполными.
5. Когда проведена проверка и что изменилось с прошлым запуском.

Если источники не открылось, нельзя уверенно утверждать «нового нет». Состояние предыдущей проверки полезно для поиска пропусков, но исторические цифры нужно заново подтверждать.

## Важное ограничение

Промпт с формулировкой «каждое утро» сам по себе не запускает задачу по расписанию. Требуется отдельная поддерживаемая автоматизация и её фактическое создание с согласия пользователя.
