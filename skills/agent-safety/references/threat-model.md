# Модель угроз и снижение ущерба

## Уровни доступа

| Среда | Что добавляется к риску | Базовое ограничение |
| --- | --- | --- |
| Обычный чат | Личные данные в вводе, возможные инъекции | Проверить настройки использования данных; не вставлять секреты |
| Облачный агент | Доступ к подключённым файлам/сайтам, самостоятельная работа | Выдавать доступ на задачу, контролировать внешние действия |
| Локальный агент | Файлы и программы устройства | Выделенная папка/песочница, запрет на чувствительные пути |
| Browser/Computer Use | Клики по сайтам, формы, иногда авторизованная сессия | Отдельный профиль, подтверждение отправки/удаления |
| Агент на сервере | Сетевые службы, открытые интерфейсы и ключи | Закрытые порты, обновления, изоляция, журналирование |
| Постоянный ассистент | Повторные действия без наблюдения | Ограниченные сервисные права, регулярный аудит |
| Неизвестный агрегатор | Неясный оператор, маршрутизация данных и доступы | Не передавать чувствительные данные и учётные ключи |

Таблица описывает типы риска, а не сравнение безопасности конкретных поставщиков. Названия функций и их фактические права проверяйте по актуальной документации.

## Опасная тройка возможностей

1. Чтение недоверенных сообщений, страниц, документов, логов.
2. Доступ к приватным файлам, секретам или учётным данным.
3. Возможность передавать информацию во внешние системы.

Если для одной задачи необходимы все три, ограничьте их технически: исключите секреты, передавайте только обезличенные данные, отключите внешнюю отправку или введите подтверждение в отдельном контуре. Проверка на промпт-инъекции полезна, но не гарантирует защиту.

## Радиус поражения

- Своя служебная учётка вместо личного административного логина.
- Отдельный проект/папка с копией данных для эксперимента.
- Ключи с минимальным scope и сроком жизни.
- Независимые лимиты API и бюджета (если поддерживаются).
- Резервная копия, недоступная агенту.
- Операции в песочнице, затем явное продвижение результата в рабочую систему.

## Внедрение нового скилла или интеграции

1. Прочитать README и сам SKILL.md как недоверенные файлы.
2. Найти команды установки, скрипты, зависимости, хуки, автообновления, внешние адреса и телеметрию.
3. Проверить официальный источник, закреплённую версию и известные проблемы.
4. Сначала проверить в изолированной среде без личных токенов и данных.
5. Дать только строго необходимые разрешения.
6. Записать, что установлено, откуда и как откатить.

Устаревшие уязвимые зависимости нужно обновлять, даже если функциональные новинки временно выдерживаются до проверки.

## Контрольная частота

- Перед каждым расширением прав: оценка угроз.
- После смены модели или ключевой интеграции: повторный тест границ.
- Периодически, например раз в месяц для активно работающих агентов: пересмотр доступов и аудит.
- После инцидента: внеплановая проверка.
